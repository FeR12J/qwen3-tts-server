Qwen3-TTS · Documentación de la API

Servidor FastAPI de texto a voz con modelos Qwen3-TTS locales y voice cloning.

Panel de administración

El panel web en /webui permite seleccionar y cargar el modelo, clonar voces, probar la síntesis reproduciendo el audio en el navegador, ajustar la configuración en tiempo de ejecución y gestionar las claves API.

Autenticación con claves API

Cuando la exigencia de clave API está activada (desde el panel, sección "Claves API"), los endpoints del servicio requieren una clave válida. Se envía de una de estas dos formas:

X-API-Key: qt-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
# o bien
Authorization: Bearer qt-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Las claves se crean y gestionan en el panel (/webui → Claves API). El endpoint /webui/docs y las rutas de información (/, /models, /voices) no requieren clave.

Generar audio (curl)

Con voz por defecto

curl -X POST http://localhost:8001/tts \
  -H "Content-Type: application/json" \
  -H "X-API-Key: qt-tu-clave-aqui" \
  -d '{
    "text": "Hola, esto es una prueba de voz.",
    "language": "Spanish",
    "speaker": "Serena",
    "instruct": "Habla con entusiasmo."
  }' \
  --output voz.wav

Con voz clonada

# 1. Clonar una voz local (voices/<nombre>/voice.wav + text.txt)
curl -X POST http://localhost:8001/voice/load \
  -H "Content-Type: application/json" \
  -d '{"voice_name": "alberto"}'

# 2. Generar con la voz clonada (se usa automáticamente)
curl -X POST http://localhost:8001/tts \
  -H "Content-Type: application/json" \
  -d '{"text": "Ahora habla la voz clonada."}' \
  --output clon.wav

# 3. Volver a la voz por defecto
curl -X POST http://localhost:8001/voice/unload

Crear una voz nueva (subiendo archivos)

Se suben el audio WAV y su transcripción con multipart/form-data. La voz se guarda en voices/<nombre>/ y se clona automáticamente:

curl -X POST http://localhost:8001/voice/create \
  -H "X-API-Key: qt-tu-clave-aqui" \
  -F "voice_name=maria" \
  -F "text=Hola, esta es la transcripción del audio de referencia." \
  -F "audio=@/ruta/al/audio.wav"

Transcripción de audio (Whisper)

El servidor incluye transcripción de audio con el modelo Whisper local (models/whisper-large-v3). El modelo se carga de forma perezosa en la primera petición y usa el dispositivo configurado (device). Formatos soportados: wav, mp3, flac, ogg, m4a.

# Transcribir (idioma automático)
curl -X POST http://localhost:8001/transcribe \
  -H "X-API-Key: qt-tu-clave-aqui" \
  -F "audio=@/ruta/al/audio.mp3"

# Transcribir forzando idioma español
curl -X POST http://localhost:8001/transcribe \
  -H "X-API-Key: qt-tu-clave-aqui" \
  -F "audio=@/ruta/al/audio.wav" \
  -F "language=es"

Respuesta: {"status":"ok","text":"...","language":"es","duration_seconds":12.3,"model":"whisper-large-v3","device":"cuda:0"}

Generar audio (Python)

import requests

API = "http://localhost:8001"
KEY = "qt-tu-clave-aqui"   # vacío si las claves están desactivadas

headers = {"Content-Type": "application/json"}
if KEY:
    headers["X-API-Key"] = KEY

resp = requests.post(f"{API}/tts", json={
    "text": "Texto a sintetizar",
    "language": "Spanish",
}, headers=headers)

resp.raise_for_status()
with open("audio.wav", "wb") as f:
    f.write(resp.content)
print("Audio guardado en audio.wav")

OpenWebUI

En OpenWebUI, configura un engine de audio (pipeline TTS) o usa la función externa apuntando a:

URL: http://HOST_DEL_SERVIDOR:8001/tts/audio/speech
API key: qt-tu-clave-aqui   (si las claves están activadas)

El endpoint acepta text o input, y devuelve audio/wav.

Configuración en tiempo de ejecución

Campos disponibles en POST /webui/api/config (todos opcionales, se persisten en config/runtime.json):

{
  "max_text_chars": 1000,          // límite de caracteres por petición
  "playback_wait_timeout": 300,    // timeout de /tts/play (segundos)
  "def_language": "Spanish",       // idioma por defecto
  "def_voice": "Serena",           // speaker por defecto
  "def_instruct": "Habla en español...",  // instrucción por defecto
  "log_level": "INFO",             // DEBUG | INFO | WARNING | ERROR
  "log_requests": true,            // registrar peticiones en requests.log
  "api_keys_enabled": false,       // exigir clave API en el servicio
  "device": "auto"                 // auto | cpu | cuda:0 | cuda:1 | ...
}

El campo device selecciona la GPU (si hay varias) o fuerza el uso de CPU: auto usa la primera GPU disponible y cae a CPU si no hay CUDA; cpu fuerza la CPU (dtype float32); cuda:N usa la GPU N. Si la GPU solicitada no existe, se usa cuda:0. El cambio se aplica al cargar el modelo. Las GPUs disponibles se pueden consultar en GET /webui/api/devices.

Gestión de claves API (curl)

# Crear clave (la clave completa solo se muestra una vez)
curl -X POST http://localhost:8001/webui/api/apikeys \
  -H "Content-Type: application/json" -d '{"name": "openwebui"}'

# Listar claves (enmascaradas)
curl http://localhost:8001/webui/api/apikeys

# Activar/desactivar una clave
curl -X POST http://localhost:8001/webui/api/apikeys/<id>/toggle

# Eliminar una clave
curl -X DELETE http://localhost:8001/webui/api/apikeys/<id>

Notas

El audio se devuelve como audio/wav. El servidor guarda una copia de cada generación en audios/ (los antiguos se limpian automáticamente al arrancar).
Las claves se almacenan como hash SHA-256. Si pierdes una clave, elimínala y crea otra.
Documentación interactiva del framework disponible en /docs (Swagger UI).
