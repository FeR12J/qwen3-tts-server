Qwen3-TTS · Documentación de la API

Servidor FastAPI de texto a voz con modelos Qwen3-TTS locales y voice cloning.

Panel de administración

El panel web en /webui permite seleccionar y cargar el modelo, clonar voces, probar la síntesis reproduciendo el audio en el navegador, ajustar la configuración en tiempo de ejecución y gestionar las claves API.

Autenticación con claves API

Cuando la exigencia de clave API está activada (desde el panel, sección "Claves API"), los endpoints del servicio requieren una clave válida. Se envía de una de estas dos formas:

Niveles de protección: Público = sin autenticación · Sí = requiere X-API-Key si la exigencia global está activada · Admin = exige siempre una clave API válida (las operaciones administrativas no quedan accesibles sin autenticación; si aún no existe ninguna clave, se permite crear la primera).

X-API-Key: qt-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
# o bien
Authorization: Bearer qt-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Las claves se crean y gestionan en el panel (/webui Claves API). El endpoint /webui/docs y las rutas de información (/, /models, /voices) no requieren clave.

Generar audio (curl)

Con voz por defecto

curl -X POST http://localhost:8001/tts \
  -H "Content-Type: application/json" \
  -H "X-API-Key: qt-tu-clave-aqui" \
  -d '{
    "text": "Hola, esto es una prueba de voz.",
    "language": "spanish",
    "speaker": "Serena",
    "instruct": "Habla con entusiasmo."
  }' \
  --output voz.wav

Con voz clonada

# 1. Clonar una voz local (voices/<nombre>/voice.wav + text.txt)
curl -X POST http://localhost:8001/voice/load \
  -H "Content-Type: application/json" \
  -d '{"voice_name": "alberto"}'

# 2. Generar con la voz clonada (se usa automáticamente)
curl -X POST http://localhost:8001/tts \
  -H "Content-Type: application/json" \
  -d '{"text": "Ahora habla la voz clonada."}' \
  --output clon.wav

# 3. Volver a la voz por defecto
curl -X POST http://localhost:8001/voice/unload

Crear una voz nueva (subiendo archivos)

Se suben el audio WAV y su transcripción con multipart/form-data. La voz se guarda en voices/<nombre>/ y se clona automáticamente:

curl -X POST http://localhost:8001/voice/create \
  -H "X-API-Key: qt-tu-clave-aqui" \
  -F "voice_name=maria" \
  -F "text=Hola, esta es la transcripción del audio de referencia." \
  -F "audio=@/ruta/al/audio.wav"

Transcripción de audio (Whisper)

El servidor incluye transcripción de audio con el modelo Whisper local (models/whisper-large-v3). El modelo se carga de forma perezosa en la primera petición y usa el dispositivo configurado (device). Formatos soportados: wav, mp3, flac, ogg, m4a.

# Transcribir (idioma automático)
curl -X POST http://localhost:8001/transcribe \
  -H "X-API-Key: qt-tu-clave-aqui" \
  -F "audio=@/ruta/al/audio.mp3"

# Transcribir forzando idioma español
curl -X POST http://localhost:8001/transcribe \
  -H "X-API-Key: qt-tu-clave-aqui" \
  -F "audio=@/ruta/al/audio.wav" \
  -F "language=es"

Respuesta: {"status":"ok","text":"...","language":"es","duration_seconds":12.3,"model":"whisper-large-v3","device":"cuda:0"}

Generar audio (Python)

import requests

API = "http://localhost:8001"
KEY = "qt-tu-clave-aqui"   # vacío si las claves están desactivadas

headers = {"Content-Type": "application/json"}
if KEY:
    headers["X-API-Key"] = KEY

resp = requests.post(f"{API}/tts", json={
    "text": "Texto a sintetizar",
    "language": "spanish",
}, headers=headers)

resp.raise_for_status()
with open("audio.wav", "wb") as f:
    f.write(resp.content)
print("Audio guardado en audio.wav")

Streaming

POST /tts/stream genera audio en streaming real: divide el texto en frases y emite cada una en cuanto termina de generarse, sin esperar a todo el texto. La primera frase llega en la primera generación; no se trata de un WAV completo troceado después.

Formatos: output_format: "wav" (por defecto, WAV streaming con cabecera de tamaño indeterminado) o output_format: "pcm" (PCM 16-bit LE; la frecuencia se indica en la cabecera X-Audio-Rate).

# Reproducir en tiempo real (aplay espera el flujo completo)
curl -N -X POST http://localhost:8001/tts/stream \
  -H "Content-Type: application/json" \
  -H "X-API-Key: qt-tu-clave-aqui" \
  -d '{"text": "Primera frase. Segunda frase. Tercera frase.", "language": "spanish"}' \
  | ffplay -nodisp -autoexit - &

# PCM sin cabecera
curl -N -X POST http://localhost:8001/tts/stream \
  -H "Content-Type: application/json" \
  -d '{"text": "Hola mundo.", "output_format": "pcm"}' \
  -H "X-API-Key: qt-tu-clave-aqui" \
  | aplay -r 24000 -f S16_LE -c 1

Las frases se dividen respetando abreviaturas (Sr.) y decimales (3.14); el límite de caracteres por frase es max_text_chars. El primer byte tarda lo que tarda la primera frase; el resto llega frase a frase.

Si streaming_enabled está en false (configuración en tiempo de ejecución), /tts/stream devuelve 404 y solo están disponibles los endpoints no-streaming.

Límites de entrada

El servidor nunca acepta entrada ilimitada. Los límites se comprueban antes de cargar o usar la GPU (errores 400 sin tocar el modelo):

  • limits.max_text_characters (por defecto 10000): longitud máxima del texto por petición.
  • limits.max_reference_audio_mb (por defecto 25): tamaño máximo del audio de referencia de clonación (reference_audio o voces locales).
  • limits.max_audio_duration_seconds (por defecto 30): duración estimada del audio generado a partir de la longitud del texto (~16 caracteres/segundo).
  • limits.max_reference_duration_seconds (por defecto 60): duración máxima del audio de referencia de clonación, verificada decodificando el archivo antes de usar GPU.
  • limits.max_voice_audio_duration_seconds (por defecto 120) y limits.max_voice_audio_bytes (50 MB): duración y tamaño máximos del audio subido para crear voces.
  • limits.max_transcribe_duration_seconds (por defecto 600) y limits.max_transcribe_audio_bytes (100 MB): duración y tamaño máximos del audio a transcribir.
  • limits.min_sample_rate (8000), limits.max_sample_rate (96000) y limits.max_channels (2): rango de sample rate y canales admitidos en audios de entrada.

La validación de audio (en AudioService.validate) no confía en la extensión del archivo: comprueba tipo MIME, bytes mágicos del contenido real, tamaño, duración, sample rate, canales y decodifica el contenido completo (rechaza archivos corruptos o sin datos antes de consumir GPU).

Variables de entorno: QWEN_TTS_LIMITS__MAX_TEXT_CHARACTERS, QWEN_TTS_LIMITS__MAX_REFERENCE_AUDIO_MB, QWEN_TTS_LIMITS__MAX_AUDIO_DURATION_SECONDS, QWEN_TTS_LIMITS__MAX_REFERENCE_DURATION_SECONDS, QWEN_TTS_LIMITS__MIN_SAMPLE_RATE, QWEN_TTS_LIMITS__MAX_SAMPLE_RATE, QWEN_TTS_LIMITS__MAX_CHANNELS, QWEN_TTS_LIMITS__MAX_VOICE_AUDIO_DURATION_SECONDS, QWEN_TTS_LIMITS__MAX_TRANSCRIBE_DURATION_SECONDS.

Textos largos

Los endpoints aceptan textos de hasta limits.max_text_characters (por defecto 10000). El texto se divide en fragmentos con utils/chunker.py antes de generar:

  • Se respetan los párrafos (nunca se corta uno a mitad si cabe en el fragmento).
  • Se respetan las frases (nunca se corta una frase a mitad si cabe).
  • Se evitan cortes artificiales: solo se parte por palabras cuando una frase/párrafo excede el tamaño máximo.
  • El tamaño máximo de cada fragmento es max_text_chars (configuración en tiempo de ejecución).

Modos de división (text.chunking, variable de entorno QWEN_TTS_TEXT__CHUNKING):

  • sentence (por defecto): fragmentos de frases completas; los párrafos nunca se mezclan dentro de un fragmento. Recomendado para /tts/stream.
  • paragraph: fragmentos de párrafos completos; solo se subdividen los párrafos que exceden el máximo.

En POST /tts (y play/audio/speech) los fragmentos se generan secuencialmente y el audio se devuelve concatenado en un solo WAV. En POST /tts/stream cada fragmento se emite en cuanto termina.

OpenWebUI

En OpenWebUI, configura un engine de audio (pipeline TTS) o usa la función externa apuntando a:

URL: http://HOST_DEL_SERVIDOR:8001/tts/audio/speech
API key: qt-tu-clave-aqui   (si las claves están activadas)

El endpoint acepta text o input, y devuelve audio/wav.

Configuración en tiempo de ejecución

Campos disponibles en POST /webui/api/config (todos opcionales, se persisten en data/runtime.json):

{
  "max_text_chars": 1000,          // límite de caracteres por petición
  "playback_wait_timeout": 300,    // timeout de /tts/play (segundos)
  "def_language": "spanish",       // idioma por defecto
  "def_voice": "Serena",           // speaker por defecto
  "def_instruct": "Habla en español...",  // instrucción por defecto
  "log_level": "INFO",             // DEBUG | INFO | WARNING | ERROR
  "log_requests": true,            // registrar peticiones en requests.log
  "streaming_enabled": true,       // habilitar el endpoint /tts/stream
  "save_audios": true,             // guardar copia de los audios generados en audios/
  "api_keys_enabled": false,       // exigir clave API en el servicio
  "device": "auto"                 // auto | cpu | cuda:0 | cuda:1 | ...
}

El campo device selecciona la GPU (si hay varias) o fuerza el uso de CPU: auto usa la primera GPU disponible y cae a CPU si no hay CUDA; cpu fuerza la CPU (dtype float32); cuda:N usa la GPU N. Si la GPU solicitada no existe, se usa cuda:0. El cambio se aplica al cargar el modelo. Las GPUs disponibles se pueden consultar en GET /webui/api/devices.

Gestión de claves API (curl)

# Crear clave (la clave completa solo se muestra una vez)
curl -X POST http://localhost:8001/webui/api/apikeys \
  -H "Content-Type: application/json" -d '{"name": "openwebui"}'

# Listar claves (enmascaradas)
curl http://localhost:8001/webui/api/apikeys

# Activar/desactivar una clave
curl -X POST http://localhost:8001/webui/api/apikeys/<id>/toggle

# Eliminar una clave
curl -X DELETE http://localhost:8001/webui/api/apikeys/<id>

Notas

El audio se devuelve como audio/wav. El servidor guarda una copia de cada generación en audios/ (los antiguos se limpian automáticamente al arrancar); se puede desactivar con save_audios.
Las claves se almacenan como hash SHA-256. Si pierdes una clave, elimínala y crea otra.
Documentación interactiva del framework disponible en /docs (Swagger UI).
